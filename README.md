# Jobescape — сайт-презентация решения

Статический сайт для показа жюри. Без зависимостей: только HTML, CSS и немного JS.

## Запуск

```bash
./serve.sh          # http://localhost:5173/
./serve.sh 8080     # другой порт
```

## Развёртывание

Сайт статический, сборки не требует. Для деплоя есть отдельная папка —
в ней только то, что отдаётся браузеру, без сборочных скриптов:

```bash
python3 _build/build_dist.py            # → ../jobescape-site
python3 _build/build_dist.py ~/куда/надо
```

Список файлов не зашит: скрипт читает страницы и кладёт то, на что они
ссылаются, плюс `vercel.json`. Папка пересоздаётся с нуля при каждом запуске,
так что удалённые картинки в ней не задерживаются.

Оттуда — `npx vercel --prod`. Либо импортировать репозиторий
на [vercel.com/new](https://vercel.com/new): тогда деплой поднимется сам
на каждый push, а `.vercelignore` оставит сборочные файлы снаружи.

## Трек «UX / UI»

Страница целиком приходит из артефакта «Jobescape — итоговое решение UX/UI».
Обновился артефакт — повторить два шага:

```bash
# 1. сохранить артефакт в HTML поверх _build/artifact-uxui.html
python3 _build/build_uxui.py   # стили → doc.css, тело → фрагмент, разделы → uxui_meta.py
python3 _build/build.py        # пересобрать страницы
```

`build_uxui.py` скоупит стили артефакта под `.doc`, выбрасывает его шапку
и пилюли-навигацию (их роль играют шапка страницы и сайдбар) и отдаёт
в `uxui_meta.py` разделы, плашки и лид — чтобы сайдбар не разъехался.

Скоупинг не трогает `@keyframes`, `@font-face` и подобные: их содержимое —
не селекторы, и приписанный `.doc` сделал бы правило невалидным (браузер
выбросит его целиком, и анимации перестанут работать). Внутрь `@media`
и `@supports` сборка заходит и скоупит вложенные правила.

Плашки в шапке артефакта проставлены руками и отстают от содержания, поэтому
те, что считаются по разметке (экраны, макеты, аргументы, состояния маскота,
токены цвета), пересчитываются, и сборка печатает, где не сошлось. Иначе шапка
обещает одно, а страница показывает другое.
В конце печатает список картинок, которых не хватает.

Если раздел надо сказать иначе, чем в артефакте, — он кладётся целиком
в `_build/uxui_patches.py`, по ключу `id` секции. Сборка подменяет раздел
и печатает, что патч применён; если раздела в артефакте больше нет —
ругается, а не тихо теряет текст. Убрать ключ = вернуть версию артефакта.

Сейчас там один патч — раздел **04 Ментор**: в артефакте он объяснял,
почему убирается выдуманная биография, а жюри прежней версии не видело.
Переписан с нуля: ментор знает весь план и подсказывает сам,
смена аватара помечена как косметика.

Картинки артефакт ждёт в `art/*.jpg`. Список не зашит: `build_art.py` читает,
на какие файлы ссылается артефакт, находит одноимённые PNG в папках хакатона
и конвертирует в JPEG шириной 1600 px.

```bash
python3 _build/build_art.py   # до build_uxui.py
```

Уже готовые файлы пропускаются, так что повторный запуск дешёвый. В конце
скрипт говорит, что лежит в `art/`, но артефактом больше не используется —
такие можно удалять. Сжатие даёт ~6 МБ вместо ~50 МБ исходников.

## Трек «Уроки»

Страница — обычный документ в той же вёрстке, что UX/UI: читается сверху вниз,
8 разделов, подсветка раздела в сайдбаре при прокрутке. Текст перенесён
из дека дословно и лежит в `_build/lessons_content.py` — правится там,
потом `python3 _build/build.py`.

Блоки, из которых собраны разделы (хелперы в `_build/blocks.py`):

| Хелпер | Что рисует |
| --- | --- |
| `hyp(…)` | Гипотеза + «что должно вырасти» — рамка в начале раздела |
| `stats([…])` | Плитки с крупными числами |
| `args([…])` | Карточки аргументов с источником |
| `idea(…)` | Гипотеза · Аргумент · Пример · Метрика (+ оговорка) |
| `finding(…)` | Находка аудита: номер, метки severity, строки разбора |
| `steps([…])` | Нумерованные шаги |
| `rl3([…])` | Таблица «что · решение · почему» |
| `table(…)` | Обычная таблица, `aligns=['','n']` — моноширинные числа |

Дек остался отдельной страницей — для показа с проектора, ссылка на него
в шапке раздела. Пересобрать дек из исходной выгрузки артефакта:

```bash
python3 _build/build_lessons_deck.py   # создаёт lessons-deck.html
python3 _build/build.py                # обновляет указатель и страницы
```

Что делает `build_lessons_deck.py`:

- вырезает слайды из набора `DROP` (сейчас — `30`, монетизация) —
  и из разметки, и из конфига анимаций `deck-motion`, где индексы позиционные;
- пересчитывает подписи «Slide N of M»;
- убирает слово «монетизация» из подзаголовка титульного слайда,
  чтобы он не обещал раздел, которого больше нет.

Чтобы вернуть слайд — убери его номер из `DROP` и пересобери.
Путь к исходнику задан в `SRC` в начале скрипта.

## Треки «Баги» и «Монетизация»

Источник — `jobescape_audit.pdf` (ручной проход 22–23.09.2026). Текст перенесён
в `_build/bugs_content.py` и `_build/money_content.py`; PDF для сборки не нужен.

Скриншоты находок лежат прямо в PDF аудита XObject-ами и вытаскиваются
без сторонних библиотек:

```bash
python3 _build/build_bugs_art.py   # art-audit/*.jpg
python3 _build/build.py
```

FlateDecode-кадры — сырые RGB-сэмплы, PNG вокруг них собирается руками;
DCTDecode — уже JPEG. Привязка «страница PDF → имя кадра» задана в `NAMES`:
если на странице появится новая картинка, скрипт скажет, что её некуда положить.

**Замазка выключена** (`REDACT = False`): аккаунт тестовый, имена на кадрах свои.
Если кадры понадобится показать за пределами команды — как просит сам аудит, —
`REDACT = True` размоет области из `BLUR` (имя ученика и почта). Координаты
заданы долями кадра, так что не зависят от его размера.

**Ссылки.** В PDF они лежат отдельно от текста, в аннотациях страниц, поэтому
текстовый извлекатель их не видит. Две записи экрана (находки 15 и 16) вшиты
в `bugs_content.py` вручную; если в аудите появятся новые ссылки, их видно так:

```bash
python3 - <<'EOF'
import re
d = open('.../jobescape_audit.pdf','rb').read()
for m in re.finditer(rb'/URI\s*\((.*?)\)', d, re.S):
    print(m.group(1).decode('latin-1'))
EOF
```

Баги: 16 находок в блоках `finding(номер, заголовок, метки, строки, pics)` —
метки красятся сами по severity (`S1` красный, `S2` оранжевый, `S3` серый,
`Предложение` синий). Макет предлагаемого сертификата — константа `CERT`
в том же файле, чистый HTML+CSS без картинок.

Монетизация: реферальная петля через `steps([...])`, точки апселла — `rl3(...)`.
Раздел 04 — слайд монетизации из дека «Уроки», который в трек 02 не вошёл.

## Как добавить контент

**Общее решение на главной.** `_build/build.py`, `index_body`, секция `id="common"`.

**Подразделы в сайдбаре.** В `PAGES` у нужной страницы добавь `subnav` —
список `(якорь, номер, название)`. Якорь должен совпадать с `id` секции
на странице; подсветка при прокрутке заработает сама.

## Готовые блоки вёрстки

Оболочка (`shell.css`) — для новых разделов:

- `.sec` + `.sec__hd` — секция с номером и заголовком
- `.shell-tbl > table` — таблица со скроллом по горизонтали
- `.slot` — пунктирный слот «ждём контент»
- `.tracks` / `.track` — карточки треков

Макеты (`doc.css`) — то же, что в треке UX/UI:

- `.hyp` — блок гипотезы, `.eff` внутри — «что должно вырасти»
- `.args > div` — карточки аргументов, `.src` — источник
- `.rl.rl3` — таблица «что · решение · почему»
- `.screen` + `.pair` — пара макетов веб / iOS, `ul.ann` — пояснения
- `.tr` — строка плана внедрения

## Правки поверх артефакта

`assets/doc.css` генерируется, поэтому всё, что надо поправить в вёрстке
артефакта, лежит в конце `assets/shell.css` — он грузится следом.

Сейчас там две правки:

1. У пояснений под экранами в артефакте `display:flex`, из-за чего каждый
   `<b>` и `<code>` внутри строки становится отдельным flex-элементом
   и уезжает вправо. Вернули строчный поток и висячий отступ.
2. `<span>` внутри подписи к иллюстрации — отдельной строкой и потише:
   им помечается второстепенное («это косметика»), а стиля для него
   в новом артефакте нет.

Текст разделов правится не здесь, а в `_build/uxui_patches.py`.
